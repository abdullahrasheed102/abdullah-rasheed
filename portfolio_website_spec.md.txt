# Portfolio Website — Project Specification

## 1. Project Goal

Build a simple, professional, modern personal portfolio website for **Muhammad Abdullah Rasheed**, an AI graduate and early-career AI Engineer.

The website should be designed primarily for:
- AI Engineer / AI Developer job applications
- AI/ML internships and junior roles
- Python + AI backend roles
- Freelance/client credibility

The website must feel **clean, light, modern, technical, and professional**.

Do NOT make it look like a generic AI-generated portfolio template.

---

## 2. Tech Stack

### Frontend
- React
- Vite
- JavaScript or TypeScript
- CSS / Tailwind CSS if useful
- React Router only if multiple pages are actually needed

### Backend
- Node.js
- Express.js

### Development
- Git
- Environment variables through `.env`
- npm

Keep the architecture simple. Do not introduce unnecessary libraries or microservices.

---

## 3. Visual Direction

### Overall Style

Use a **light-colored minimalist design**.

Preferred characteristics:
- White / off-white background
- Dark charcoal text
- One restrained accent color
- Plenty of whitespace
- Clean typography
- Subtle borders
- Soft shadows
- Rounded corners, but not excessive
- Subtle hover transitions
- Professional spacing

Avoid:
- Dark mode as the primary design
- Neon colors
- Excessive gradients
- Glowing effects
- Particle backgrounds
- Animated 3D objects
- Excessive glassmorphism
- Huge decorative AI graphics
- Overly rounded "startup template" cards
- Excessive animations

The website should look good even with animations disabled.

### Suggested Color Direction

Use approximately:

- Background: `#FAFAF8` or similar warm white
- Primary text: `#171717`
- Secondary text: `#5F6368`
- Borders: `#E7E5E4`
- Accent: muted blue / indigo / emerald

Do not use many colors.

---

## 4. Typography

Use a modern, readable sans-serif font.

Good options:
- Inter
- Geist
- Manrope

Use strong hierarchy:

- Large but controlled hero heading
- Medium section headings
- Comfortable body text
- Small metadata text

Avoid oversized headings that consume most of the screen.

# 15. Backend Requirements

Create a small Express backend.

Suggested structure:

```text
server/
├── src/
│   ├── routes/
│   │   └── contact.js
│   ├── controllers/
│   │   └── contactController.js
│   ├── middleware/
│   └── app.js
├── package.json
└── .env.example
```

For the first version, the backend only needs to handle the contact form.

Do not create unnecessary APIs.

If email sending is implemented, use environment variables for credentials.

Never hardcode secrets.

# 17. Responsiveness

The site must work properly on:

- Desktop
- Laptop
- Tablet
- Mobile

Do not simply shrink the desktop layout.

Mobile should have:
- Proper spacing
- Readable typography
- Stacked project cards
- Functional navigation
- Large enough buttons
- No horizontal overflow

---

# 18. Accessibility

Implement basic accessibility:

- Semantic HTML
- Proper heading hierarchy
- Alt text for meaningful images
- Keyboard-accessible buttons and links
- Visible focus states
- Good color contrast
- Form labels
- Accessible mobile navigation

---

# 19. Performance

Keep the site lightweight.

Avoid:
- Huge image files
- Unnecessary JavaScript libraries
- Heavy animation libraries
- Autoplay video backgrounds
- Unnecessary API requests

Use lazy loading for project images if needed.

# 21. Code Quality

Important:

- Use reusable React components.
- Keep components reasonably small.
- Avoid duplicated code.
- Use meaningful names.
- Keep content separate from UI where practical.
- Do not hardcode secrets.
- Use `.env.example`.
- Handle API errors properly.
- Add loading/error states where appropriate.
- Keep dependencies minimal.

Do not over-engineer the application.

---

# 22. Content Rules

Do NOT invent:

- Companies
- Job titles
- Technologies
- Project results
- Metrics
- Clients
- Testimonials
- Certifications
- Awards

If information is missing, create a clearly marked placeholder or ask for the information.

Accuracy is more important than making the portfolio look impressive.

---

# 23. Animation Rules

Animations should be subtle.

Allowed:
- Fade-in
- Small slide-up
- Hover transitions
- Smooth scrolling
- Button transitions

Avoid:
- Constant movement
- Parallax everywhere
- Cursor-following effects
- Particle systems
- Excessive scroll animations
- 3D scenes

The website should still feel polished without animation.

---

# 24. Final Quality Standard

Before considering the website complete, verify:

- [ ] Desktop responsive
- [ ] Mobile responsive
- [ ] Navigation works
- [ ] All links work
- [ ] Resume download works
- [ ] GitHub links work
- [ ] LinkedIn link works
- [ ] Contact form works
- [ ] Backend handles errors
- [ ] No secrets committed
- [ ] No fake portfolio information
- [ ] No console errors
- [ ] No broken images
- [ ] Good Lighthouse performance
- [ ] Good accessibility basics
- [ ] Clean visual hierarchy

The final result should look like the portfolio of a serious early-career AI engineer—not a template demonstrating frontend effects.
